# 2026-07-22 工作日志

## 修复: 多顶层类 Java 文件的增量打包

### 背景
用户报告 `JxrlAuditPolicyService.java` 编译出 34 个不同名的 .class 文件（责任链模式，含主类 + AbstractHandler + PipelineChain + HandlerChainContext + 30 个 *Handler），但增量打包只出了主类的 class。

### 根因分析（3 个 bug）
1. **编码问题**: `extract_class_names()` 用 `fs::read_to_string` 读 Java 源文件，GBK 编码会失败返回空列表
2. **路径问题**: `java_file` 用 `project_root.join("src/main/java").join(relative_to_src)` 硬编码，当 SVN 路径有前缀目录（如 `entss/src/main/java/...`）时找不到文件
3. **正则问题**: `(?:class|interface|enum|@interface)\s+(\w+)` 缺少 `\b` 词边界，可能误匹配 `subclass` 等

### 修复内容（均在 `src-tauri/src/lib.rs`）
1. `extract_class_names`: 改为 `fs::read` 读字节 + `String::from_utf8_lossy`，正则加 `\b`，结果去重
2. 新增 `collect_inner_classes(parent_dir, simple_name, &mut results)` 辅助函数
3. `src/main/java/` 分支 + `src/` 分支: java_file 改为 `project_root.join(&local_path)`，内部类扫描改用 `collect_inner_classes`，兄弟类也收集内部类
4. 回退分支: 两遍扫描 — 先找主类定位目录，再从 Java 源文件提取兄弟类名

### 验证
- `cargo check` 编译通过（仅 4 个预存的 unused import 警告）

## 修复（第二轮）: find_java_source 路径查找

### 问题
第一轮修复中 `java_file = project_root.join(&local_path)` 仍有缺陷：SVN 日志路径包含项目前缀（如 `entss/src/main/java/...`），但用户的本地路径配置可能已经包含该前缀（如 `D:\workspace\entss`），拼出来变成 `D:\workspace\entss\entss\src\main\java\...` — 双重前缀，文件找不到。

### 修复
新增 `find_java_source(project_root, class_base)` 函数，基于包路径（`class_base`，如 `com/dckj/kkgl/service/JxrlAuditPolicyService`）而非 SVN 路径来定位 Java 源文件：
1. `project_root/src/main/java/<package>/Foo.java`（标准 Maven）
2. `project_root/src/<package>/Foo.java`（简单 src）
3. `project_root/<subdir>/src/main/java/...`（一级深度，处理 SVN 前缀）
4. `project_root/<subdir>/<subdir>/src/main/java/...`（二级深度）

三个分支（`src/main/java/`、`src/`、回退）全部替换为使用 `find_java_source`。
添加 `eprintln!` 诊断日志。
